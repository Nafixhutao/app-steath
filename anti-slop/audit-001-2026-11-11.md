## HIGH — Hard Gate (absolute)

### 1. R-02 — Em dash in UI strings (13 occurrences, 7 files)
The em dash character (`—`) appears in user-facing copy, violating the hard ban.

Sentence-level (classic slop signature):
- `database-panel.tsx:25` — "Unavailable — the node did not answer"
- `database-panel.tsx:189` — "saved but not live yet — redeploy this Project's Services"
- `database-panel.tsx:261` — "Over the storage limit — the Database was stopped"
- `deployments-panel.tsx:167` — "unavailable — Deployments are blocked"
- `custom-domain-panel.tsx:239` — "Not configured — use the CNAME instead"
- `volume-panel.tsx:24` — "Unavailable — the node did not answer"
- `volume-panel.tsx:121` — "saved but not live yet — redeploy this Service"
- `environment-panel.tsx:138` — "saved but not live yet — redeploy this Service"
- `abuse-reports/panel.tsx:168` — "— Organization suspended"

Placeholder glyph (bare `—` as empty-value marker):
- `deployments-panel.tsx:27,32,224` — `"—"` for empty duration/commit
- `runtime-panel.tsx:158` — `"—"` for empty container id

*Reason: em dash is the top copywriting slop marker; replace with `,` / `:` / `.` / `()` or an empty-state glyph like `–`/`—` replaced by `"N/A"`.*

### 2. R-24 + R-26 + R-38 — Dead legal & recovery links on login page
`app/page.tsx` ships anchors that do nothing and lead nowhere:
- "terms" / "privacy policy" / "cookie policy" (`href="#terms"` etc., `preventDefault()`)
- "Forgot … email or password?" (`href="#email"`/`#password`, `preventDefault()`)

*Reason: these are nav items to non-existent destinations (R-24), dead controls (R-26), and realistic-looking content with no backing page (R-38). Should point to real pages or be removed / labelled "Coming soon".*

### 3. R-26 — Dead controls in the account menu
`components/sidebar.tsx`:
- "Profile Settings" button — no `onClick`, does nothing.
- "Refer and Earn" button — no `onClick`, does nothing.
- Notification bell (`notification-button`) — `onClick` only calls `setProfileOpen(false)`; never opens any notification view.

*Reason: interactive elements must have real behavior or be removed.*
*Note: the auth "SSO / Google / GitHub" buttons are `disabled` with a "…coming soon" notice that lives only in `onClick`, so the notice can never fire because disabled buttons don't receive clicks.*

### 4. R-34 + R-21 + R-26 — Theme toggle is non-functional
`components/sidebar.tsx` ships a light / dark / system toggle (`theme-row`, `:root` is hardcoded dark). Clicking only updates local `useState`; there is no `data-theme` attribute, no `classList` mutation, no `localStorage`, and no light stylesheet (`app/globals.css` has no light palette). Grep confirms the only `documentElement` use is scroll-locking.

*Reason: a shipped theme toggle where the light mode does not exist is a broken control (R-26) and a theme that does not work in both modes (R-34); dark is forced without a working "give the user a choice" (R-21). Either implement light mode or remove the toggle and keep a deliberate dark default (a PaaS console has a valid dark rationale).*

### 5. R-03 — Mobile tap targets below 44px
`app/globals.css` mobile topbar controls sit under the 44px minimum:
- `.mobile-topbar-actions button` — 36px × 36px
- `.mobile-account-avatar` — 24px × 24px

*Reason: buttons below the 44px tap target on mobile; expand the hit area (padding/negative margin) without changing the visual size.*

## MEDIUM — Purpose-Gate (technique allowed, reason required)

### 6. R-04 — Icon set is Lucide with no written reason
`components/sidebar.tsx` imports the `lucide-react` set (`strokeWidth=1.7`), the recognisable thin-stroke "AI default" library. The glyphs are at least content-relevant (Inbox → Inbox, ChartPie → Overview), but the choice is not documented.

*Reason: record why Lucide (consistency, bundle size, coverage) rather than "it's the default"; otherwise consider a more distinctive set.*

### 7. R-06 — Typeface is the default pick without a written reason
`app/layout.tsx` loads `Geist` + `Geist_Mono` from `next/font/google` — the antislop-named default. No brand-character rationale is recorded.

*Reason: either write the one-line reason (developer-tool legibility, neutrality to let the mascot carry personality) or pick a face that reflects the "Stealth / kurama cat" identity.*

## LOW — Quality Locks

### 8. R-29 — Palette exceeds 2–3 core + 1 accent
Beyond neutrals, the console carries four accent hues plus semantic red:
blue `#186cee` (primary auth), green `#00734b` (create project/service + success), gold `#d8c783` (create organization + warnings), purple `#b5a8ff` (links, service URLs, volume bar), red (danger).

*Reason: consolidate to a single accent (purple or blue) and treat green/gold/red as semantic states only, or document the intentional multi-accent system.*
